## Slide 4 – AI vs Traditional Programming
Traditional Programming: - Human experts define explicit rules for every scenario - Data + rules → output - Becomes complex and hard to maintain as scenarios grow

AI / Machine Learning: - Systems learn patterns from data and outcomes - Data + outcomes → model - Model generalizes and adapts to new data

Visual: Rule-based vs data-driven comparison

Visualization Suggestions: - Split-screen layout: left (Traditional), right (AI/ML) - Flow diagrams: - Traditional: Data + Rules → Output - AI/ML: Data + Outcomes → Model → Predictions - Use different colors (grey for traditional, blue/green for AI) - Callout box summarizing "Rules vs Learning from Data"

## Slide 5 – AI vs Traditional Programming (Pros and Cons)
PROS and CONS Traditional Programming: - Pros: - Predictable outputs for defined inputs - Easier to debug specific rules - Transparent decision-making process - Easier to implement for simple, well-defined tasks - User can trust the system behavior - Cons: - Inflexible to new scenarios - Requires extensive rule definition - Struggles with complex patterns - Maintenance becomes cumbersome as rules increase

AI / Machine Learning: - Pros: - Adapts to new data and scenarios - Can handle complex patterns - Reduces need for explicit rule definition - Continuously improves with more data - Can uncover insights not apparent to humans - Cons: - Requires large datasets - Less predictable outputs - May need retraining with new data - Can be a "black box" – hard to interpret decisions - May inherit biases from training data

Visualization Suggestions: - Two-column comparison table: Traditional vs AI/ML, with Pros/Cons rows - Use thumbs-up / warning icons to distinguish pros and cons - Color-coded background for pros (green/light) and cons (yellow/orange) - Short summary banner at bottom: "Choose based on problem complexity and data availability"

Slide 4 – Machine Learning vs Traditional Programming
Traditional Programming: - Humans explicitly define rules/logic in code - Input: data + rules → Output - System behavior only changes when a developer updates the rules

Machine Learning: - System learns patterns (rules) from examples - Input: data + expected outcomes (labels) → Trained model - Model can make predictions on new, unseen data - Performance can improve as more/better data is collected

Visualization Suggestions: - Split screen comparison: Left (Traditional) vs Right (ML) - Flow diagrams with boxes and arrows showing process flow - Traditional: [Data] + [Rules] → [Output] (linear, rigid) - Color coding: Red/orange for Traditional, Blue/green for ML - Icons: Wrench/tool for traditional programming, Brain/network for ML - "VS" divider in center with contrasting visual treatment - Use different arrow styles (straight vs curved) to emphasize difference

Slide 5 – Types of Machine Learning
Main learning paradigms:

Supervised learning: Learn from labeled data (input + correct output)
Unsupervised learning: Find patterns in unlabeled data
Semi-supervised learning: Mix of labeled and unlabeled data (high level only)
Reinforcement learning: Learn by trial and error with rewards/penalties (conceptual overview)
Note: AI-900 focuses mainly on supervised and unsupervised learning; semi-supervised and reinforcement are introduced conceptually.

Visualization Suggestions: - Four-quadrant grid or 2x2 matrix layout for the four types - Icon for each type: - Supervised: Tagged/labeled icons - Unsupervised: Cluster/grouping icons - Semi-supervised: Half-labeled icons - Reinforcement: Reward/trophy icons - Color code each type differently - Emphasize Supervised and Unsupervised with larger boxes or spotlight effect - Info box at bottom for the note about AI-900 focus

Slide 6 – Supervised Learning
Concept: - Uses labeled data (input + correct output) - Learns a mapping from inputs (features) to outputs (labels)

Common problem types: - Classification: Predicts discrete labels (e.g., spam vs not spam) - Regression: Predicts continuous values (e.g., house prices)

Examples: - Email spam detection (classification) - House price prediction (regression)

Visualization Suggestions: - Two-panel layout: Classification (left) vs Regression (right) - Classification visual: Decision boundary separating two classes (spam/not spam) - Regression visual: Scatter plot with trend line showing continuous prediction - Data flow diagram: [Input Data + Labels] → [Model] → [Predictions] - Icons: Email with spam badge, house with price tag - Highlight "labeled data" concept with tagged data point illustrations

Slide 7 – Unsupervised Learning
Uses unlabeled data
Focuses on discovering hidden patterns or structures
Common tasks: - Clustering (grouping similar data) - Anomaly detection (finding outliers)

Examples: - Customer segmentation (clustering) - Detecting unusual behavior in transactions (anomaly detection)

Slide 8 – Common Machine Learning Terminology and Problem Types
Features: Input variables used for predictions
Labels: Target output variable in supervised learning
Training Data: Data used to train the model
Testing Data: Data used to evaluate model performance
Model: The learned function that maps inputs to outputs
Overfitting: When a model learns training data too well and performs poorly on new data
Underfitting: When a model is too simple to capture underlying patterns in the data
Generalization: The model's ability to perform well on unseen data
Accuracy: A metric to evaluate classification models
Bias: Systematic error in predictions due to incorrect assumptions in the learning algorithm
Key idea: Choose problem type based on the business question

Slide 9 – Machine Learning Lifecycle
Typical ML lifecycle:

Data collection
Data preparation
Model training
Model evaluation
Model deployment
Emphasis: ML is an iterative process—models are improved over time as new data and feedback become available. The lifecycle always starts from the business problem and loops back when things change.

Visualization Suggestions: - Circular diagram with 5 labeled phases - Arrows showing iteration from deployment back to data collection - Highlight the current phase when presenting follow-up slides

Slide 10 – Machine Learning Lifecycle: Data Collection
1. Data Collection: Gather data from sources such as databases, spreadsheets, sensors, web APIs, or manual entry. Tools: SQL databases, data lakes, web scraping tools. Azure examples: Azure SQL Database, Azure Data Lake Storage. - Examples: - Collecting customer purchase records from a sales database - Gathering images from an online repository for image classification - Recording sensor data from IoT devices for predictive maintenance - Quality and relevance of data are critical for successful ML projects

Visualization Suggestions: - Central hub where multiple data sources feed into one data store - Icons for database, spreadsheet, sensors, web APIs, manual entry - Callout note emphasizing "Data quality matters"

Slide 11 – Machine Learning Lifecycle: Data Preparation
2. Data Preparation: Clean, transform, and engineer features to make data suitable for modeling Tools: Data wrangling tools, ETL pipelines, feature stores. - Common tasks: - Handling missing values - Normalizing numerical features - Converting text data into numerical format (e.g., TF-IDF for text) - Encoding categorical variables - Removing duplicates and outliers - Label encoding for supervised learning - Splitting data into training and testing sets - Well-prepared data leads to better model performance

Visualization Suggestions: - Before/after view: messy raw data vs clean structured data - Simple pipeline: Raw data → Cleaning → Feature engineering → Train/Test split - 80/20 split graphic for training vs testing

Slide 12 – Machine Learning Lifecycle: Model Training
3. Model Training: Use algorithms to learn patterns from training data Algorithms: Linear regression, logistic regression, decision trees, random forests, SVM, neural networks - Steps: - Selecting an appropriate algorithm - Feeding training data into the algorithm - Tuning hyperparameters to optimize performance - Goal: Minimize error on training data while avoiding overfitting

For AI-900, you only need to understand the role of algorithms (learning from data to make predictions), not the mathematical details or implementation.

Visualization Suggestions: - Diagram: Training data → Algorithm → Trained model - Example icons for a few algorithm families (line, tree, neural net) - Slider/knob icons to represent hyperparameter tuning

Slide 13 – Machine Learning Lifecycle: Model Evaluation
4. Model Evaluation: Evaluate model performance using metrics: - Classification: Accuracy, precision, recall, F1-score - Regression: MAE, MSE (optionally R-squared at high level) - Techniques: Cross-validation, confusion matrix analysis - Goal: Ensure model generalizes well to unseen data

For AI-900, focus on the conceptual meaning of metrics (how often the model is correct, misses positives, or raises false alarms) rather than formulas.

Visualization Suggestions: - Simple 2×2 confusion matrix for a binary classification problem - Small comparison table for Accuracy, Precision, Recall, and F1-score - Bar chart comparing average error across models (e.g., MAE/MSE)

Slide 14 – Machine Learning Lifecycle: Model Deployment
5. Model Deployment: Deploy the trained model so it can be used in real-world applications - Considerations: + Scalability, latency, security, and compliance + Monitoring for performance degradation + Handling model versioning and rollback + Ensuring compliance with data privacy regulations Deployment options: - Cloud services (Azure Machine Learning endpoints, Azure Functions, Azure App Service) - On-premises servers - Edge devices (IoT, mobile) - Embedded in applications via APIs

Goal: Make the model accessible, secure, and reliable for end users or automated systems.

Visualization Suggestions: - Architecture diagram: Model → Azure ML endpoint/API → Application → Users - Icons for cloud, on-premises server, and edge device - Monitoring dashboard mockup for model performance
