# Claude Certified Architect – Foundations

## 1. Giới thiệu về Chứng nhận này

Chứng nhận Claude Certified Architect – Foundations xác nhận rằng người hành nghề có thể đưa ra

các quyết định sáng suốt về đánh đổi khi triển khai các giải pháp thực tế với Claude. Kỳ thi này

kiểm tra kiến thức nền tảng về Claude Code, Claude Agent SDK, Claude API và Model

Context Protocol (MCP), những công nghệ cốt lõi được dùng để xây dựng các ứng dụng cấp production với

Claude.

Các câu hỏi trong kỳ thi này được xây dựng dựa trên các tình huống thực tế rút ra từ các use case thực của khách hàng,

bao gồm xây dựng hệ thống agentic cho customer support, thiết kế các pipeline nghiên cứu multi-agent,

tích hợp Claude Code vào các workflow CI/CD, xây dựng các công cụ năng suất cho developer, và trích xuất

dữ liệu có cấu trúc từ các tài liệu phi cấu trúc. Thí sinh không chỉ phải thể hiện kiến thức khái niệm

mà còn cả khả năng phán đoán thực tiễn về kiến trúc, cấu hình và các đánh đổi trong

triển khai production.

Hướng dẫn này là tài liệu tham chiếu có thẩm quyền cho các thí sinh chuẩn bị tham gia kỳ thi. Tài liệu mô tả

nội dung kỳ thi, liệt kê các domain và các task statement được kiểm tra, cung cấp câu hỏi mẫu và

đề xuất các chiến lược ôn tập. Hãy đọc toàn bộ tài liệu trước khi đăng ký lịch thi.

làm khung cho một tập câu hỏi. Trong kỳ thi, 4 scenario được trình bày và được chọn ngẫu nhiên từ

toàn bộ tập 6 scenario dưới đây.

Scenario 1: Customer Support Resolution Agent

hệ thống backend của bạn thông qua các tool Model Context Protocol (MCP) tùy chỉnh (get_customer, lookup_order,

process_refund, escalate_to_human). Mục tiêu của bạn là đạt 80%+ first-contact resolution trong khi vẫn biết khi nào

cần escalate.

## 6. Các Mục tiêu Chi tiết theo Domain

Mỗi domain dưới đây liệt kê các task statement được kiểm tra, cùng với kiến thức và kỹ năng được đo lường

tương ứng với từng mục. Các câu hỏi thi được viết dựa trên các mục tiêu này.

## Domain 1: Agentic Architecture & Orchestration

Task Statement 1.1: Thiết kế và triển khai agentic loop cho việc thực thi task tự động

Kiến thức về:

- Vòng đời của agentic loop: gửi request đến Claude, kiểm tra stop_reason ("tool_use" vs
"end_turn"), thực thi các tool được yêu cầu, và trả kết quả về cho vòng lặp tiếp theo

- Cách tool result được append vào conversation history để model có thể suy luận về hành động

tiếp theo

- Sự khác biệt giữa việc ra quyết định do model dẫn dắt (Claude suy luận xem nên gọi tool nào

tiếp theo dựa trên context) với các decision tree hoặc chuỗi tool được cấu hình sẵn

Kỹ năng về:

- Triển khai control flow của agentic loop sao cho tiếp tục khi stop_reason là "tool_use" và
kết thúc khi stop_reason là "end_turn"

- Thêm tool result vào conversation context giữa các iteration để model có thể đưa thông tin mới

vào quá trình suy luận của nó

- Tránh các anti-pattern như parse các tín hiệu ngôn ngữ tự nhiên để xác định việc kết thúc loop,
đặt iteration cap tùy ý làm cơ chế dừng chính, hoặc kiểm tra nội dung text của assistant như một
dấu hiệu hoàn thành

Task Statement 1.2: Điều phối multi-agent system với pattern coordinator-subagent

Kiến thức về:

- Kiến trúc hub-and-spoke, trong đó một coordinator agent quản lý toàn bộ giao tiếp giữa các
subagent, xử lý lỗi, và định tuyến thông tin

- Cách subagent hoạt động với context cô lập—chúng không tự động kế thừa conversation history
của coordinator

- Vai trò của coordinator trong việc phân rã task, delegation, tổng hợp kết quả, và quyết định
nên gọi subagent nào dựa trên độ phức tạp của query

- Rủi ro khi coordinator phân rã task quá hẹp, dẫn đến việc bao phủ không đầy đủ các chủ đề
nghiên cứu rộng

Kỹ năng về:

- Thiết kế coordinator agent phân tích yêu cầu của query và chọn động subagent nào cần gọi thay
vì luôn định tuyến qua toàn bộ pipeline

- Phân chia phạm vi nghiên cứu giữa các subagent để giảm thiểu trùng lặp (ví dụ: gán các
subtopic hoặc loại nguồn khác nhau cho từng agent)

- Triển khai các vòng lặp tinh chỉnh lặp đi lặp lại, trong đó coordinator đánh giá output tổng hợp
để tìm lỗ hổng, re-delegate cho các subagent tìm kiếm và phân tích với các query có mục tiêu cụ
thể, và gọi lại synthesis cho đến khi độ bao phủ đủ tốt

- Định tuyến toàn bộ giao tiếp của subagent qua coordinator để đảm bảo observability, xử lý lỗi
nhất quán, và kiểm soát luồng thông tin

Task Statement 1.3: Cấu hình việc gọi subagent, truyền context, và spawning

Kiến thức về:

- Task tool như là cơ chế để spawn subagent, và yêu cầu rằng allowedTools phải bao gồm "Task"
để coordinator có thể gọi subagent

- Rằng context của subagent phải được cung cấp tường minh trong prompt—subagent không tự động
kế thừa context của parent hay chia sẻ memory giữa các lần gọi

- Cấu hình AgentDefinition bao gồm description, system prompt, và các giới hạn tool cho

từng loại subagent

- Quản lý session dựa trên fork để khám phá các hướng tiếp cận khác nhau từ một baseline phân
tích chung

Kỹ năng về:

- Đưa toàn bộ phát hiện từ các agent trước trực tiếp vào prompt của subagent (ví dụ: truyền kết
quả web search và output phân tích tài liệu cho subagent synthesis)

- Sử dụng các định dạng dữ liệu có cấu trúc để tách nội dung khỏi metadata (source URL, tên tài
liệu, số trang) khi truyền context giữa các agent nhằm bảo toàn attribution

- Spawn các subagent song song bằng cách phát ra nhiều Task tool call trong một response duy nhất
của coordinator thay vì qua các turn riêng biệt

- Thiết kế prompt cho coordinator chỉ rõ mục tiêu nghiên cứu và tiêu chí chất lượng thay vì các
hướng dẫn thủ tục từng bước, để subagent có thể thích ứng linh hoạt

Task Statement 1.4: Triển khai multi-step workflow với các pattern enforcement và handoff

Kiến thức về:

- Sự khác biệt giữa enforcement ở mức lập trình (hook, prerequisite gate) và hướng dẫn dựa trên
prompt cho việc sắp xếp thứ tự workflow

- Khi yêu cầu tuân thủ mang tính tất định (ví dụ: xác minh danh tính trước các thao tác tài
chính), chỉ dùng prompt instruction có tỷ lệ thất bại khác không

- Các giao thức handoff có cấu trúc cho việc escalation giữa chừng, bao gồm thông tin khách hàng,
phân tích root cause, và các hành động được đề xuất

Kỹ năng về:

- Triển khai các prerequisite ở mức lập trình để chặn các tool call downstream cho đến khi các
bước prerequisite hoàn thành (ví dụ: chặn process_refund cho đến khi get_customer đã trả về một
customer ID đã được xác minh)

- Phân rã các yêu cầu của khách hàng có nhiều mối quan tâm thành các item riêng biệt, sau đó
điều tra từng item song song sử dụng context chung trước khi tổng hợp thành một giải pháp thống
nhất

- Biên soạn các bản tóm tắt handoff có cấu trúc (customer ID, root cause, số tiền hoàn, hành
động được đề xuất) khi escalate lên human agent—những người không có quyền truy cập vào
conversation transcript

Task Statement 1.5: Áp dụng Agent SDK hook để chặn tool call và chuẩn hóa dữ liệu

Kiến thức về:

- Các pattern hook (ví dụ: PostToolUse) chặn tool result để biến đổi trước khi model

xử lý chúng

- Các pattern hook chặn các tool call đi ra để thực thi các quy tắc tuân thủ (ví dụ: chặn hoàn
tiền vượt ngưỡng)

- Sự khác biệt giữa việc dùng hook để có các đảm bảo mang tính tất định với việc dựa vào prompt
instruction để có sự tuân thủ mang tính xác suất

Kỹ năng về:

- Triển khai PostToolUse hook để chuẩn hóa các định dạng dữ liệu không đồng nhất (Unix timestamp,
ISO 8601, mã trạng thái dạng số) từ các MCP tool khác nhau trước khi agent xử lý chúng

- Triển khai các hook chặn tool call để chặn các hành động vi phạm policy (ví dụ: hoàn tiền vượt
quá $500) và chuyển hướng sang các workflow thay thế (ví dụ: escalation lên người)

- Chọn hook thay vì enforcement dựa trên prompt khi các business rule yêu cầu sự tuân thủ

được đảm bảo

Task Statement 1.6: Thiết kế chiến lược phân rã task cho các workflow phức tạp

Kiến thức về:

- Khi nào dùng các pipeline tuần tự cố định (prompt chaining) so với phân rã động thích ứng dựa
trên các phát hiện trung gian

- Các pattern prompt chaining chia nhỏ việc review thành các bước tuần tự (ví dụ: phân tích từng
file riêng lẻ, sau đó chạy một lượt tích hợp cross-file)

- Giá trị của các kế hoạch điều tra thích ứng, tạo ra các subtask dựa trên những gì được phát
hiện ở mỗi bước

Kỹ năng về:

- Chọn các pattern phân rã task phù hợp với workflow: prompt chaining cho các review đa khía
cạnh có thể dự đoán được, phân rã động cho các task điều tra mở

- Chia nhỏ các code review lớn thành các lượt phân tích cục bộ theo từng file cộng với một lượt
tích hợp cross-file riêng biệt để tránh attention bị pha loãng

- Phân rã các task mở (ví dụ: "thêm test toàn diện cho một legacy codebase") bằng cách trước
tiên lập bản đồ cấu trúc, xác định các khu vực có tác động cao, sau đó tạo một kế hoạch ưu tiên
có thể thích ứng khi phát hiện ra các dependency

- Multi-pass review: chia các review lớn thành các pass phân tích cục bộ theo từng file cộng với các pass tích hợp cross-file để tránh attention dilution và các finding mâu thuẫn

## 17. Phụ lục

Các công nghệ và khái niệm

Danh sách sau đây bao gồm các công nghệ và khái niệm có thể xuất hiện trong bài thi:

- Claude Agent SDK — định nghĩa agent, agentic loop, xử lý stop_reason, hooks (PostToolUse,

chặn lời gọi tool), sinh subagent thông qua Task tool, cấu hình allowedTools

- Model Context Protocol (MCP) — MCP server, MCP tool, MCP resource, cờ isError, mô tả tool,

phân phối tool, cấu hình .mcp.json, mở rộng biến môi trường

Claude Certification Program Exam guide

- Claude Code — thứ bậc cấu hình CLAUDE.md (user/project/directory), .claude/rules/ với
YAML frontmatter phạm vi theo đường dẫn, .claude/commands/ cho slash command, .claude/skills/ với

SKILL.md frontmatter (context: fork, allowed-tools, argument-hint), plan mode, thực thi trực tiếp,

lệnh /memory, /compact, --resume, fork_session, Explore subagent

- Claude Code CLI — cờ -p / --print cho chế độ non-interactive, --output-format json, --json-schema cho

đầu ra CI có cấu trúc

- Claude API — tool_use với JSON schema, các tùy chọn tool_choice ("auto", "any", chọn tool bắt buộc),

các giá trị stop_reason ("tool_use", "end_turn"), max_tokens, system prompt

- Message Batches API — tiết kiệm 50% chi phí, cửa sổ xử lý tối đa 24 giờ, custom_id để

tương quan request/response, polling để kiểm tra hoàn tất, không hỗ trợ multi-turn tool calling

- JSON Schema — trường bắt buộc so với tùy chọn, kiểu enum, trường nullable, mẫu "other" + chuỗi chi tiết,

strict mode để loại bỏ lỗi cú pháp

- Pydantic — kiểm tra schema, lỗi kiểm tra ngữ nghĩa, vòng lặp validation-retry

- Các tool tích hợp — Read, Write, Edit, Bash, Grep, Glob — mục đích và tiêu chí lựa chọn của chúng

- Few-shot prompting — ví dụ có chủ đích cho các tình huống mơ hồ, minh họa định dạng,

khả năng tổng quát hóa cho các mẫu mới

- Prompt chaining — phân rã tác vụ tuần tự thành các lượt xử lý tập trung

- Quản lý context window — ngân sách token, tóm tắt lũy tiến, hiệu ứng lost-in-the-middle,

trích xuất context, file scratchpad

- Quản lý session — khôi phục session, fork_session, session có tên, cô lập context session

- Chấm điểm độ tin cậy — độ tin cậy theo từng trường, hiệu chỉnh bằng tập validation có nhãn, lấy mẫu

phân tầng để đo tỷ lệ lỗi
